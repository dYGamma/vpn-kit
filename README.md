# vpn-kit

Обвязка вокруг [3x-ui](https://github.com/MHSanaei/3x-ui) для личного VPN: пять
входов разных протоколов, генератор подписок под каждое приложение, выдача
доступов через Telegram-бота и сторож, который сам находит утечки.

Ставится на чистую машину двумя командами: `bootstrap.sh` поднимает основание
(панель, Xray, входы, Hysteria2, сертификат, nginx), `install.sh` — саму обвязку.

Собрано на боевом узле для семьи и друзей в России. Всё, что здесь написано,
проверено на живом трафике; отдельно вынесены грабли, на которые мы наступили —
их полезнее прочитать до установки, чем после.

## Зачем это нужно

Обычная схема «весь трафик в тоннель» в России ломает половину сервисов: банки
отбивают платежи с иностранных адресов, Госуслуги и маркетплейсы не пускают,
доставка не определяет город. Задача обвязки — **российское уводить мимо
тоннеля**, чтобы сервисы видели домашний адрес человека, а всё остальное
отправлять через сервер.

Ключевая мысль, на которой держится вся конструкция: **на сервере это
неисполнимо**. У него есть только два исхода — сходить на сайт самому (тогда
сайт видит адрес сервера) или отказать. Мимо тоннеля уводит **только клиент**,
поэтому главная работа обвязки — доставить правила в приложение и убедиться,
что они применились.

## Что внутри

### Пять входов

| Протокол | Транспорт | Зачем |
|---|---|---|
| VLESS + Reality | TCP 443 | основной |
| VLESS + Reality | TCP 8443 | второй домен прикрытия |
| Hysteria2 | UDP | выручает, когда режут TCP |
| Hysteria2 + obfs | UDP | когда узнают отпечаток QUIC |
| Shadowsocks-2022 | TCP | не TLS вообще, вся TLS-аналитика мимо |

Разные протоколы отказывают по-разному — в этом и смысл. Когда под DPI лёг
Reality, живым остался Hysteria2; когда начали ловить QUIC — Shadowsocks.

Панель 3x-ui знает только свои два входа VLESS. Про остальные три клиент
узнаёт из строк в таблице `client_external_links`, а их держит в актуальном
виде `bin/client-links-sync.py` (таймер раз в минуту): завёл человека в
панели — через минуту у него в подписке все пять узлов, перезапускать ничего
не нужно.

### Генератор подписок (`service/`)

Встроенный генератор панели отдаёт всем один и тот же список ссылок, а правила
обхода прикладывает HTTP-заголовком, который читают далеко не все клиенты.
`sub.py` вместо этого собирает **свой формат под каждое ядро**:

| Адрес | Формат | Кому |
|---|---|---|
| `/s/<id>/singbox` | sing-box JSON | Hiddify, Karing, sing-box |
| `/s/<id>/clash` | mihomo YAML | Clash Verge, Koala Clash |
| `/s/<id>/xray` | массив конфигов Xray | v2rayN, NekoRay, INCY |
| `/s/<id>/links` | base64-ссылки + заголовок `Routing` | Happ |
| `/s/<id>/incy` | ссылки + профиль маршрутизации | INCY |
| `/s/<id>` | определяется по `User-Agent` | остальные |

Во всех форматах правила лежат **внутри конфига**, а не приезжают боковым
каналом. Список доменов при этом один — он берётся из настроек панели
(`subRoutingRules`), и `direct_domains()` раскладывает его по синтаксису каждого
ядра. Правишь список в одном месте — меняются все форматы.

### Выдача доступов через Telegram (`bot/`)

Человек пишет боту, владельцу приходит заявка с командами, человек получает
персональную ссылку на страницу установки. Владелец отвечает одной командой:

```
/vpn list            заявки в очереди
/vpn ok <номер>      выдать доступ
/vpn no <номер>      отказать
/vpn off <tg_id>     отозвать
/vpn re <tg_id> ...  ответить человеку от лица бота
```

Частые вопросы бот разбирает сам — `bot/vpn-faq.py`, восемь тем: не
подключается, медленно, «отключите VPN», оплата, какое приложение, не
обновилась подписка, потерял ссылку, сколько стоит. Что не опознал — уходит
владельцу вместе с готовой командой `/vpn re`, и он отвечает одной строкой.
Ответы даются только тем, у кого доступ уже есть: почти все начинаются с
«у тебя есть личная страница», и человеку без доступа это было бы враньём.

Заявка создаётся **только при внятной просьбе**: на первое «привет» бот сам
представляется и спрашивает, при следующем неответе мягко напоминает, после
пяти — замолкает. Иначе владельца дёргает каждый случайный клик.

Клиент заводится **без перезапуска Xray** — через `xray api adu`. Это
принципиально: перезапуск рвёт сессии всем сразу.

### Сторож утечек (`bin/leak-scan.py`)

Сервер видит каждый адрес, который проксирует. Раз в час сторож сверяет их со
списком обхода и делит находки на четыре группы:

* **правила не работают** — домен есть в списке обхода, но трафик всё равно
  пришёл на сервер. Значит клиент правила не применяет;
* **новый российский домен** — которого в списках нет;
* **российский адрес без имени** — QUIC или соединение по голому адресу;
* **похоже на российский сервис на чужом домене** — по названию бренда.

Именно так нашлись `dodopizza.io`, `ozon.io`, `payture.com`, `payselection.com`
и `sbercdn.com` — их нет ни в одном публичном списке, и без сторожа они
находились бы по жалобам «не проходит оплата».

### Панель `bin/vpnctl`

TUI без зависимостей: службы и таймеры, входы с проверкой портов, люди с
трафиком и временем последнего обновления подписки, отчёт сторожа, очередь
заявок, журнал нарушений. Действия: пересчитать утечки, синхронизировать ключи
резервных входов.

Колонка «подписку брал» — самая полезная: если приложение подписку не тянуло, у
человека старые правила, что бы вы ни правили на сервере.

### Зеркало баз правил (`bin/rules-mirror.sh`)

Клиенты тянут наборы правил при первом запуске, а GitHub из России доступен
через раз — без правил подписка бесполезна ровно в момент установки. Скрипт
раз в сутки зеркалирует 18 файлов на свой же сервер: наборы `geosite`/`geoip`,
список российских сервисов, блокирующих зарубежные адреса, и списки
заблокированного в России.

## Установка

Нужна свежая Ubuntu 22.04+ на x86_64 и свободные порты 443, 8443, 2053.
Два шага:

```bash
git clone <этот репозиторий> vpn-kit && cd vpn-kit
sudo ./bootstrap.sh
```

Одна команда. `bootstrap.sh` поднимает основание и, когда оно собрано целиком,
сам запускает `install.sh`. Вводить руками ничего не нужно: ключи, секреты и
сертификат он делает сам.

Ключи: `--dry-run` печатает план и на диск не пишет (прогоните сначала так —
увидите заодно конфликты портов), `--no-install` останавливается на основании,
не ставя обвязку.

### Что делает `bootstrap.sh`

1. ставит пакеты, которых не хватает;
2. создаёт `/etc/vpn-issue/config` со свежими секретами (`SECRET`, секретный
   путь страницы, секретный путь API) — если файла ещё нет;
3. ставит 3x-ui официальным установщиком, задаёт порт панели и учётку;
4. генерирует ключи Reality (`xray x25519`) и заводит **два входа** —
   443 с прикрытием `www.kinopoisk.ru` и 8443 с `www.samsung.com`;
5. выпускает сертификат Let's Encrypt **на IP-адрес** через acme.sh и вешает
   автопродление с перезапуском панели, Hysteria и nginx. Не вышло (адрес
   недоступен снаружи по порту 80) — делает временный самоподписанный, чтобы
   узел собрался целиком, и пробует получить настоящий на каждом следующем
   прогоне;
6. ставит Hysteria2, пишет конфиг с авторизацией по базе панели и включает
   прыжки по портам 20000-50000;
7. кладёт конфиг nginx и страницу установки.

**Скрипт идемпотентный и трусливый.** Всё, что уже стоит и настроено, он не
трогает: не переписывает конфиг Hysteria, не лезет в таблицу `inbounds`, если
там уже есть входы, не переиздаёт сертификат. Это не вежливость — перезапись
ключей Reality означает, что ни один существующий клиент больше не
подключится, а перезапись конфига Hysteria рвёт сессии всем разом.

Единственное, чего он не гарантирует, — **настоящий сертификат на голый IP**:
их выдаёт не любой CA и только когда адрес доступен снаружи. Пока не вышло,
узел живёт с самоподписанным: службы поднимаются, но клиенты сертификату не
поверят. Своим можно подменить в любой момент — положите в
`/root/cert/ip/{fullchain,privkey}.pem`.

### Если ставите не на VPS, а на домашнюю машину: про NAT

Коротко: **на домашнем компьютере узел работать не будет, пока вы не откроете
к нему дорогу снаружи.** Дело не в скрипте и не в настройках — так устроен
домашний интернет.

**Что происходит.** У вашего компьютера адрес вида `192.168.x.x` — он
существует только внутри квартиры. В интернете виден один адрес, и он
принадлежит роутеру. Когда телефон из города пытается подключиться к вашему
узлу, он стучится на роутер, а тот не знает, какой из домашних машин отдать
это соединение, и молча его выбрасывает. Наружу выглядит как «сервер не
отвечает», хотя все службы работают.

**Что делает скрипт.** Видит частный адрес, сам находит настоящий внешний и
пытается открыть порты через UPnP — это когда роутер по просьбе программы сам
создаёт правило. Многие домашние роутеры так умеют, но у части людей UPnP
выключен в настройках. Тогда скрипт честно печатает, что открыть, и работает
дальше с самоподписанным сертификатом.

**Что открыть руками, если UPnP не сработал.** В настройках роутера ищите
«Проброс портов», «Port Forwarding» или «Virtual Server» и заведите правила на
адрес вашей машины:

| Порт | Протокол | Зачем |
|---|---|---|
| 443 | TCP | основной вход |
| 8443 | TCP | второй вход |
| 2053 | TCP | страница с настройками для людей |
| 80 | TCP | нужен только на время выпуска сертификата |
| 36712 | UDP | Hysteria2 |
| 20000-50000 | UDP | прыжки по портам, без них Hysteria просто работает на одном |

**Когда не поможет ничего.** Если провайдер выдал роутеру адрес из диапазонов
`10.*`, `100.64-127.*` или `192.168.*` — вы за NAT провайдера, и входящие
соединения до вашего роутера не доходят в принципе. Скрипт это распознаёт и
говорит прямо. Лечится только белым адресом (у провайдера это обычно платная
услуга) или переносом узла на обычный VPS.

**И честно про смысл.** Домашний узел в России даёт на выходе ваш же домашний
адрес. Заблокированное в стране он не откроет — для этого нужен сервер за
границей. Дома такой узел имеет смысл разве что как вход в свою же домашнюю
сеть.

### Что делает `install.sh`

Раскладывает скрипты, ставит юниты, поднимает Shadowsocks-2022 и
обфусцированный Hysteria, наполняет зеркало правил и выдаёт ссылки клиентам.
Заглушки (`SERVER_IP`, `PAGE_PATH`, `API_PATH`) он подставляет из
`/etc/vpn-issue/config` **при копировании** и останавливается, если хоть одна
осталась на месте. Повторный запуск ничего не портит.

## Как прикрутить к своему боту

Сервис слушает `127.0.0.1:8791`, наружу его отдаёт nginx по секретному пути.
Все методы кроме двух требуют заголовок `X-Auth: <SECRET>`.

| Метод | Что делает |
|---|---|
| `POST /touch` | обращение человека; сам решает, создавать заявку или сперва спросить |
| `POST /request` | создать заявку напрямую |
| `POST /approve` | выдать доступ, возвращает ссылку |
| `POST /deny` | отказать |
| `POST /revoke` | отозвать доступ |
| `POST /list` | очередь заявок и число людей |
| `POST /leaks` | отчёт сторожа утечек |
| `GET /info?sub=<id>` | данные для страницы, без секрета |
| `GET /dl/<slug>` | переходник на свежий релиз приложения |

`GET /info` секрета не требует намеренно: его защищает сам код подписки — не
зная кода, получить нечего.

Пример: выдать доступ по заявке №7.

```bash
curl -s -H "X-Auth: $SECRET" -H 'Content-Type: application/json' \
     -d '{"req_id":7}' https://SERVER_IP:2053/API_PATH/approve
```

Мост `bot/vpn-gate.sh` — рабочий пример на shell: превращает обращения в заявки,
пишет владельцу команды и отправляет человеку ссылку. Его можно взять как
образец или дёргать API напрямую из своего бота.

## Грабли

Список того, что стоило нам простоев и вечеров.

**Однопоточный сервер авторизации делит два входа Hysteria на двоих.**
`bin/hysteria-auth.py` спрашивают ДВА процесса — обычный вход и обфусцированный,
— и каждый держит соединение открытым (HTTP/1.1, keep-alive у Go-клиента).
Однопоточный `HTTPServer` обслуживает по одному соединению за раз и
возвращается к `accept` только когда предыдущее закроют: первый спросивший
занимает сервер на всю свою keep-alive паузу, второй ждёт и получает таймаут.
Наружу это выглядит так: **из двух входов работает ровно один, а после простоя
они меняются местами**. Клиент проигравшего видит
`authentication error, HTTP status code: 302` — 302 отдаёт маскировка, потому
что авторизация не ответила вовремя. Люди жалуются «работает через раз», а в
логах сервера всё живо.
Диагностический приём: чередовать попытки между двумя входами. Ровно один
работает, а после двух минут тишины выигрывает тот, кто спросил первым —
значит, дело в разделяемом сериализованном ресурсе.
Лечится `ThreadingHTTPServer` + `daemon_threads = True`. **Любая служба,
которую спрашивают два и более процессов, обязана быть многопоточной.**

**Одно правило `GEOIP,private` роняло весь конфиг Clash.** В конфиге mihomo это
была единственная строка, ради которой ядро лезло на GitHub за базой MMDB.
Не скачало — **не запускается весь конфиг**, а не одно правило:
`can't initial GeoIP: can't download MMDB`. Из России GitHub доступен через раз,
то есть подписка ломалась ровно в момент установки. Заменено на девять
`IP-CIDR`/`IP-CIDR6` с диапазонами частных сетей — они неизменны, база для них
не нужна. Правило шире: **в конфигах клиентов не должно остаться ни одной
внешней зависимости, кроме вашего зеркала правил**, и проверять это надо
настоящим ядром в сети без доступа к GitHub.

**Фоновый процесс наследует flock родителя и глушит его целиком.** Поллер
берёт самолок (`exec 7>.poll.lock; flock -n 7`), а в конце запускает фоновую
задачу. `flock` живёт на открытом файле, а не на процессе, поэтому дескриптор
уезжает в ребёнка и держится всё его время. Пока ребёнок работает, каждый
следующий тик молча выходит: не забираются новые сообщения, не работает выдача
доступов. Ни ошибки, ни строки в логе — просто «бот молчит».
Лечение — закрыть свои замки у ребёнка: `... >/dev/null 2>&1 7>&- 8>&- &`.
Проверка в две строки:

```bash
bash -c 'exec 7>/tmp/t.lock; flock -n 7 || exit 9; sleep 20 & exit 0'
flock -n /tmp/t.lock true && echo свободен || echo занят ребёнком
```

**Табуляция как разделитель полей съедает пустое поле.** Для `read` табуляция —
пробельный символ, поэтому у человека без `username` текст сообщения уезжал в
поле имени, сервис получал пустой текст и не видел просьбы: заявка не
создавалась, человек ждал зря. Разделять только `\x1f`.

**`install -m 644` снимает бит запуска.** Разложенный так скрипт вызывается
напрямую и молча ничего не делает: вывод обычно уходит в `/dev/null`, и
`Permission denied` не попадает никуда. Раскладывать только `install -m 755`,
после этого дёрнуть файл без аргументов и убедиться, что он печатает подсказку
(код 126 = не запускается).

**Панель не умеет Shadowsocks-2022.** Если завести такой вход через её таблицу
`inbounds`, она при генерации конфига **теряет серверный пароль** (в SS2022 он
задаётся на входе, а не у клиентов), и Xray падает с
`shadowsocks_2022: create service > missing password` — ложатся все
пользователи. Такие протоколы держите отдельным процессом (`units/xray-ss.service`),
а панели отдавайте только ссылки.

**Ссылки клиентам можно добавлять без перезапуска панели** — через таблицу
`client_external_links` (`kind='link'`). Панель отдаёт их в подписке сразу. Это
единственный безопасный способ добавить узел.

**Откат базы панели при её работе не работает.** Она держит файл открытым и на
перезапуске пишет своё состояние обратно — удалённая строка возвращается.
Сначала `systemctl stop x-ui`, только потом подмена файла.

**Прыжки Hysteria по портам забирают весь UDP диапазона.** Правило
`REDIRECT --to-ports` в `ExecStartPost` перехватывает UDP на всём диапазоне
(обычно 20000-50000). Служба на порту из этого диапазона тихо лишается UDP: TCP
работает, UDP уходит в чужой процесс. **Новые входы ставьте выше диапазона** и
проверяйте именно UDP — TCP-проверка этого не покажет.

**`geosite:category-ru` включает `include:tld-ru`, то есть ВСЕ `.ru`.** Для
заблокированного в России это приговор: вы сами отправляете запрос мимо
тоннеля, провайдер его режет, сайт не открывается вовсе. Лечится **порядком
правил**: заблокированное обязано стоять выше российского. Чинить нужно ровно
пересечение «заблокировано И на `.ru`» — это пара десятков адресов, а не весь
дамп реестра.

**Xray не пропускает неизвестный код geosite, а роняет весь конфиг.** Ссылка на
`geosite:ru` (такого кода в базе нет) валит запуск целиком:
`illegal domain rule`. На встроенную базу клиента опираться нельзя — её
содержимое вам неизвестно. Держите явный список домёнов плюс `geoip`.

**Размер ClientHello решает всё на мобильном интернете.** Отпечаток
`fp=chrome` в uTLS включает постквантовый ключ, приветствие раздувается до 1760
байт, у оператора не влезает в один сегмент, и DPI выкидывает второй — тот, где
SNI. В логах при этом `REALITY: failed to read client hello` и ни одной
успешной сессии. Замеры: chrome 1760, firefox 1893, safari 1541,
**edge / ios / randomized — 517**. Ставьте `fp=edge`.

**Домен прикрытия нельзя выбирать наугад.** Reality при каждом рукопожатии
ретранслирует приветствие на этот домен, поэтому домен обязан принять
конкретный отпечаток клиента. Антибот-защита части сайтов отбивает `fp=edge`, и
вход умирает даже с петли на самом сервере. Российский домен с «прибитым» пулом
адресов не годится: оператор сверяет SNI с адресом назначения. Берите крупный
CDN с плавающим пулом.

**Конфиги обязательно проверять настоящими ядрами.** `sing-box check` и
`mihomo -t` находят то, что глазами не видно: старый формат блока `dns`
удаляется в sing-box 1.14, `global-client-fingerprint` из mihomo уже убран.
Версия формата `.srs` тоже важна: 1 → sing-box 1.8+, 2 → 1.10+, 3 → 1.11+,
4 → 1.13+. Положите v4 — у всех, кто старее 1.13, подписка не встанет.

**Проверять формат файла, а не размер.** Законный набор правил из 39 домёнов
весит 474 байта, и порог «меньше 500 — мусор» его отбраковал. `.srs`
начинается с `SRS` и байта версии, `.mrs` — это zstd (`28 b5 2f fd`).

**Российские сервисы на зарубежных домёнах не покрывает ничто.** `dodopizza.io`,
`ozon.io`, `sbercdn.com` живут на AWS и Cloudflare, поэтому их не ловит ни
`geosite:category-ru`, ни `geoip:ru`. Симптом характерный: **приложение
работает, падает только оплата** — российский эквайринг не пропускает платежи с
иностранных хостинговых адресов. Отсюда и нужен сторож утечек.

**Сервисы «покажи мой адрес» обязаны идти напрямую.** Приложения опрашивают
`ipify.org`, `ifconfig.me`, `checkip.amazonaws.com` и сравнивают ответ с
адресом, который видит их собственный сервер. Через тоннель эхо-сервис вернёт
чужую страну, бэкенд увидит домашний адрес — расхождение и есть детект. Один
эхо-сервис оставьте в тоннеле: по нему человек проверяет, что VPN работает.

**Панель кеширует настройки в памяти.** После правки `subRoutingRules` в базе
её собственный путь `/sub/` отдаёт прежние правила до перезапуска. Свой
генератор читает базу на каждый запрос, поэтому перезапуск ради изменения
правил не нужен — достаточно перевести человека на новый адрес.

## Чего это не решает

С апреля 2026 российские приложения обязаны определять VPN **на самом
устройстве**: сетевые интерфейсы, `TRANSPORT_VPN`, перечисление установленных
VPN-клиентов, сканирование локального порта. Проверено: запросы Госуслуг до
сервера не доходят вовсе — то есть идут напрямую с домашнего адреса, — и
приложение всё равно отказывается работать.

Маршрутизацией это не лечится: нельзя спрятать то, чего в трафике нет. На
Android помогает вынести такие приложения в отдельный профиль, на iOS не
помогает ничего — там любой клиент обязан создавать интерфейс `utun`.
Единственное полное решение — унести тоннель на роутер, тогда на телефоне не
остаётся ни клиента, ни интерфейса, ни локального порта.

Отдельно про локальный порт: клиент поднимает SOCKS на `127.0.0.1`, и любое
приложение на том же устройстве может через него сходить наружу, узнав адрес
вашего сервера в обход всех правил. Запароленный локальный вход есть в Happ,
Karing и Throne; в конфигурации sing-box из этого набора локального порта нет
вовсе — только `tun`.
